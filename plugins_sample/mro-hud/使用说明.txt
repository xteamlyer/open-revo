================================================================
 MRO 硬件监控 · OpenRevo 插件包  v2.1
 移植自 mro_monitor 0.293.6.3 / 0.293.6.3-beta23.6.3
 适用 OpenRevo v0.9.x（open-revo.exe）
================================================================

【这是什么】
把 mro_monitor 那套「CPU/GPU 温度 · 风扇转速 · 功耗 · 频率 · 显存」的
实时监控界面，做成 OpenRevo 原生插件。温度/风扇/功耗/占用等数据直接复用
OpenRevo 微内核已经采好的遥测，不再和 OpenRevo 抢驱动、抢 EC。

本包含三个插件：mro-monitor 可单独使用；mro-hud 与 mro-hud-settings 必须配套使用。

【重要 · 配套安装】
  「MRO HUD」与「MRO HUD · 设置」必须一起安装、一起启用：
    · 只开「MRO HUD」：不会直接显示 HUD，而是弹出一张整卡警告，
      提示「请先开启「MRO HUD · 设置」插件」；开启设置插件后提示自动消失；
    · 只开「MRO HUD · 设置」：设置页会自动尝试启用主程序，
      若仍未恢复会提示「未检测到 MRO HUD 主程序」。
  无论单独下载哪一个，都请把另一个也装上，否则无法使用完整功能。
  （插件列表里的说明也已标注这一点。）

  1) mro-monitor  ——「MRO 硬件监控台」（标签页）
     完整仪表盘：4 张监控卡 + 强冷/性能模式控制条 + 温度走势图 + 显存卡 + 系统信息条。
     在 OpenRevo 顶栏胶囊栏出现「MRO 硬件监控台」页签；
     右上角「独立视窗运行」可把它弹成独立窗口，当副屏监控台用。

  2) mro-hud      ——「MRO HUD」（桌面挂件）★ v2.1 纯显示
     复刻 mro_monitor 紧凑悬浮窗的两行布局：
       GPU:  49°  1.9G  2818 RPM · 56%  18.5W  7%  ▮  2.0GB  ▮
       CPU:  62°  4.7G  2789 RPM · 56%  32.4W  30% ▮  11.8GB ▮
     依次是：温度、频率(GHz)、风扇转速·转速占比、功耗(W)、占用率、占用条、
     显存/内存占用、占用条。底部一行接入 RTSS：FPS、帧时间、1% Low、前台进程名。

     置顶、无边框、跳过任务栏，整卡可拖动，位置自动记忆。
     （宿主窗口本身不支持透明，所以 HUD 用「逐像素透明覆盖层」实现：
      页面把自身光栅化成带 alpha 的 PNG 发给伴随代理，代理用分层窗口
      (UpdateLayeredWindow) 逐像素显示，背景真正透明、能直接看到游戏；
      原 WebView 设为不可见但仍接收鼠标，拖动和点 RTSS 标签照常。
      卡片底色只放在 .bg 图层、文字放在 .inner 图层，各调各的不透明度。
      圆角由伴随代理调用 DwmSetWindowAttribute(DWMWCP_ROUND) 实现。）
     排版：窗口 490×104，数值 12px 纯白（次要项 90% 白），温度加粗，
     GPU 标签亮绿 / CPU 标签亮青，进度条 6px；FPS 行数字 22px。
     对比度按「深色背景 + 纯白文字」调过，比早期版本更清楚。
     默认 Ctrl+Alt+H 显示/隐藏 HUD，可在设置页改。
     RTSS 未运行时，伴随代理会自动把它拉起来 —— 不需要先开微星小飞机。
     v2.1 起 HUD 只负责显示，不再自带齿轮和设置面板：
     外观与 1% Low 全部在 OpenRevo 里的「MRO HUD · 设置」标签页调整。

  3) mro-hud-settings ——「MRO HUD · 设置」（标签页）★ v2.1 新增
     悬浮 HUD 的独立设置页，作为 OpenRevo 的一个页签存在，不再挤在悬浮窗里：
     深色 / 玻璃 / 无底纹 / 透明四种背景、背景不透明度、字体不透明度、整体大小、窗口置顶、
     1% Low 显示开关与统计窗口（15 / 30 / 60 / 120 秒），
     带实时预览，并直接显示当前 FPS / 帧时间 / 1% Low / 窗口均值 / 采样帧数，
     改完就能在同一个页面里看到 1% Low 有没有按预期变化。

【悬浮 HUD 的数据从哪来】
  OpenRevo 遥测：温度、频率、风扇 RPM、功耗、占用、显存、供电等；
  本地只读代理 mro_agent.exe：
      - 系统内存已用/总量（GlobalMemoryStatusEx）
      - RTSS 共享内存里的 FPS / 帧时间 / 前台游戏进程
  OpenRevo 没有的两项按实际情况显示，不编造：
      - 风扇「· 56%」是「转速 / 满转 5000 RPM」的比例，不是 EC 占空比。
        EC 占空比寄存器不对外暴露（mro_monitor 是直接读 EC 才拿到的），
        鼠标悬停该字段会提示这一点。
      - 内存来自本地代理；代理离线时显示 --，并会自动请宿主重新拉起。
      - RTSS 行的四种状态：
          「传感器代理离线」  代理没起来，挂件会自动重试拉起；
          「RTSS 未运行」     代理正在自动启动 RTSS（装了 RTSS 才会成功）；
          「RTSS 就绪」       RTSS 已运行，等待前台游戏出帧；
          「FPS 144 6.9 ms」  已抓到前台游戏的帧率。
      - 点一下右下角的「RTSS」小标签，可手动再触发一次启动。

【RTSS 集成说明（只读）】
  - 读取 RTSS 的共享内存 RTSSSharedMemoryV2（与 HWiNFO/Afterburner 读法相同），
    取当前前台进程对应的条目，计算 FPS = 帧数 / 采样时长、帧时间 = 1 / FPS；
  - 不注入游戏、不加载 RTSSHooks、不修改 RTSS 配置、不往 RTSS OSD 写任何文字；
  - 无需先启动微星小飞机：代理发现 RTSS 未运行会自动拉起它。查找顺序：
    启动参数 --rtss-path -> 环境变量 RTSS_PATH -> 注册表 Uninstall 信息 ->
    Program Files 默认目录 -> 微星小飞机同级目录 -> **插件自带的 rtss 目录**；
  - 需要 RTSS 处于运行状态，并且游戏在 RTSS 启动之后启动（RTSS 只在进程创建时挂钩）；
  - 独占全屏游戏里 OpenRevo 的悬浮窗本身仍会被挡（Windows 顶层窗口的物理限制），
    这是和 RTSS 原生 OSD 的差别：我们只是读取 RTSS 的数据，不接管它的 OSD。
    需要游戏内叠加显示时，请继续用 RTSS / HWiNFO 的 OSD。

【插件自带 RTSS（客户端免安装）】
  - 位置：mro-hud\rtss\，是一份精简的便携版 RTSS（约 21 MB），
    从已安装的 RTSS 目录复制而来，去掉视频编码插件、帮助文档、SDK 等无关内容；
  - 作用：客户端电脑**没有安装 RTSS** 时，插件直接启动这一份，用户无需单独安装；
  - 优先级：系统里装了 RTSS 就优先用系统的（避免两份实例抢同一块共享内存）；
    系统里没装才用自带的。设置页的 RTSS 状态后面会标「插件自带」以示区分；
  - 已验证：把系统 RTSS.exe 改名模拟"未安装"后，代理能自动启动自带的这份，
    共享内存签名 0x52545353、version 0x00020015、entry_size 12416 全部正常；
  - 依赖：RTSS 需要 VC++ 2015-2022 运行库（VCRUNTIME140.dll）。
    Win10/11 游戏机基本都有；如果设置页显示「RTSS 启动失败」，
    装一下 https://aka.ms/vs/17/release/vc_redist.x64.exe 即可；
  - 自带 RTSS 的配置写在它自己目录里（rtss\Profiles\），不会污染系统安装的那份；
  - 如果不需要自带版本，直接删掉 mro-hud\rtss 目录即可，代理会自动回落到系统 RTSS。

【全屏游戏里 HUD 不显示】
  原因：独占全屏（Exclusive Fullscreen）时游戏独占显示输出，任何窗口——
        包括置顶窗口——都盖不上去。这是 Windows 的显示模型决定的，不是插件的问题。
        无边框窗口（Borderless Windowed）则可以正常叠加。
  已做：代理每秒探测一次 HUD 中心点有没有被别的窗口盖住，被盖就重新置顶，
        所以「无边框全屏切回来 / 游戏抢焦点后 HUD 掉到下面」这类情况能自愈。
  提示：检测到前台窗口铺满整个显示器时，设置页「帧率读数」下方会显示黄色提示。
  处理：在游戏显示设置里改成「无边框窗口 / Borderless Windowed」；
        如果只有「全屏」和「窗口」两项，选窗口后把分辨率设成显示器原生分辨率，
        效果等同于无边框全屏。

【本地代理 mro_agent.exe】
  - 位置：mro-hud\agent\mro_agent.exe，由 OpenRevo 的「伴随服务」机制
    在打开挂件时自动拉起（清单 service 声明 port 18946、auto_start/auto_stop）；
  - 只监听 127.0.0.1:18946，接口：
        GET /api/ping         -> {"ok":true,...}
        GET /api/sensors      -> {"ram_used_mb":...,"fps":...,"fps_1pct_low":...,
                                  "fps_avg_window":...,"low_bins":...,"low_frames":...,
                                  "low_span_ms":...,"app":...,"rtss_running":true}
        GET /api/rtss/start   -> 手动启动 RTSS，返回 {"started":true/false,"running":...}
        GET /api/hud/settings -> 读写 HUD 设置（bg/bg_alpha/opacity/topmost/show_low/low_window）
  - RTSS 自动启动默认开启；启动参数加 --no-rtss-autostart 可关闭，
    --rtss-path "D:\...\RTSS.exe" 可指定自定义路径；
  - 代理退出时不会关闭 RTSS（RTSS 会继续正常工作，方便游戏里继续统计帧率）；
  - 只读，不联网、不写注册表、不安装驱动、不注入其他进程；
  - 源码 mro-hud\agent\mro_agent.cs 一并附带，可自行审计或重新编译：
        双击 mro-hud\agent\build.cmd 即可（会自动找 .NET Framework 编译器，
        编译失败时保留旧的 mro_agent.exe 并备份为 mro_agent.exe.bak）；
  - 若你的机器不需要 RTSS/内存数据，可以删掉 agent 目录并去掉 manifest.json
    里的 service 段，HUD 仍会正常显示其余指标（内存与 RTSS 行为空）。

【安装】
方式 A（推荐，直接双击）
  双击本目录下的 install.cmd，脚本会把三个插件复制到
      %APPDATA%\OpenRevo\plugins\
  完成后打开（或重启）OpenRevo。

方式 B（手动）
  1. 在资源管理器地址栏输入 %APPDATA%\OpenRevo\plugins 回车；
  2. 把 mro-monitor、mro-hud、mro-hud-settings 三个文件夹整体复制进去
     （目录结构必须是 plugins\mro-hud\manifest.json 这样，注意 agent 子目录要一起复制）；
  3. 打开 OpenRevo →「插件」页 → 右上角「刷新」；
  4. 在插件列表里启用「MRO 硬件监控台」「MRO HUD」「MRO HUD · 设置」。

启用后：
  - 标签页：顶栏胶囊栏多出「MRO 硬件监控台」与「MRO HUD · 设置」，点进去即可；
  - 悬浮 HUD：首次出现在屏幕中央，拖动可移位（位置会被记住）。
    打开挂件时，界面会主动请 OpenRevo 拉起 mro_agent.exe；插件列表卡片右侧
    会出现服务状态指示灯（绿色=在线）。关掉挂件会停掉代理，但不会关闭 RTSS。

【HUD 设置页（MRO HUD · 设置）】
  - 入口：OpenRevo 顶栏「MRO HUD · 设置」标签页（也可点右上角「独立视窗运行」）；
    v2.1 起悬浮 HUD 里不再有齿轮按钮，设置只在这里改；
  - 背景样式：深色（深灰蓝渐变）/ 玻璃（深灰蓝底 + 冷白细边）/
    无底纹（极深灰）/ 透明（完全无背景，直接看到游戏）。
    HUD 是**真正的两层结构**，由代理的逐像素透明覆盖层显示：
      .bg    背景图层，opacity = 背景不透明度，渐变和亮边一起淡出
      .inner 字体图层，opacity = 字体不透明度，只管文字和进度条
    两层完全独立：调背景不会连带把字变淡，调字也不会动背景；
  - 「透明」预设：直接把 .bg 背景图层去掉（display:none），只保留字体图层，
    覆盖层上只有文字、没有底色，文字直接浮在游戏画面上（N 卡性能层那种效果）。
    注意：这是通过「页面光栅化成 PNG + 代理分层窗口」实现的，
    不是靠宿主窗口透明（open-revo 0.9.5 的插件窗口不支持透明）。
    交互：在 HUD 任意位置按住即可整块拖动（覆盖层自己处理拖动，位置会自动记住，
    重启后回到上次的位置）；点右下角 RTSS 标签可手动启动 RTSS。
    若覆盖层出问题，设置页「逐像素透明覆盖层」开关可关掉，退回普通不透明卡片。
  - 快捷键（三个，均可自定义）：默认
      Ctrl+Alt+H  显示 / 隐藏 HUD
      Ctrl+Alt+J  切换 1% Low 显示
      Ctrl+Alt+K  切换点击穿透（需先开启窗口置顶）
    点按钮后直接按下组合键即可录制，Esc 取消，清除按钮可以关掉快捷键；
    需要至少一个修饰键（Ctrl / Alt / Shift / Win），支持 A-Z、0-9、F1-F24；
    如果注册失败（被其他程序占用），卡片右上角会显示「注册失败」，悬停看原因；
  - 三个独立滑块（背景与字体彻底分开）：
      背景不透明度  0% ~ 100%，控制 .bg 背景图层的浓淡。100% 为实心卡片，
                    0% 时背景彻底消失、只剩文字浮在游戏上。深色 / 玻璃 /
                    无底纹三种都生效；选「透明」时该滑块自动隐藏（没有背景可调）；
      字体不透明度  20% ~ 100%，只作用在文字和进度条上，完全不影响背景。
                    想让 HUD 存在感更低又不想背景变淡时调这个；
      整体大小      70% ~ 160%，同时缩放窗口尺寸和内容（基础 490×104）。
                    窗口尺寸按 DPI 换算（125% 屏下 490 CSS = 612 物理），
                    页面用 calc(基础 × 系数) 真重排，放大不糊也不裁切；
  - 窗口置顶：开关立即通过 SetWindowPos 作用于 HUD 窗口；关闭后会被普通窗口盖住，
    重启挂件仍按此设置恢复；
  - 点击穿透：只在「窗口置顶」开启时可用（否则置灰）。开启后给 HUD 窗口加
    WS_EX_TRANSPARENT，鼠标直接穿到下面的游戏，HUD 变成纯显示层。
    注意：开启后无法再拖动或点击 HUD，要关掉请回到这个设置页；
    关闭置顶会自动同时关闭穿透；
  - 显示 1% Low：控制 HUD 帧率行里那个「1% xx」是否显示；
  - 1% Low 统计窗口：15 / 30 / 60 / 120 秒，决定用多长的历史算低帧；
  - 左侧实时预览 + 帧率读数（FPS / 帧时间 / 1% Low / 窗口均值 / 采样帧数），
    改完就能当场确认效果；
  - 滑块/按钮改动后自动保存（防抖 160ms）；
  - 设置保存在 %APPDATA%\OpenRevo\plugins\mro-hud\settings.ini；
  - HUD 每秒从代理同步一次，保存后约 1 秒画面变化，无需重启；
  - 代理未运行时，设置页会自动请求宿主启动 mro-hud 的伴随服务，也可点「代理离线 · 点此启动」。

【1% Low 是怎么算的（v2.2 起改用逐帧数据）】
  旧版（v1.2 及以前）有三个问题，导致 1% Low 既偏高又乱跳：
    1) 只累积 12 秒样本，窗口太短，一有波动整体就跟着跳；
    2) 把 100ms 内的平均帧时间当作一个样本，单帧卡顿被平均抹平，读数偏乐观；
    3) 用 floor(n*0.99) 取排序后的下标，样本少时等于直接取最大值，
       既不是「1%」也不是「平均」，噪声极大。
  另外 RTSS 的 dwFrames 每满 1000ms 就会清零重新计数，跨越清零的那一次采样
  会算出「半截帧数 / 整段时长」，得到翻倍的假帧时间，旧版没有识别这种情况。

  v2.2 主路径 —— 直接读 RTSS 的逐帧帧时间数组：
    - RTSS 的 OSD entry 里除了帧计数，还存了一个约 1000 帧的逐帧帧时间环形缓冲，
      位置在 entry 偏移 416（= 324 字节基础头 + 92 字节统计扩展），单位微秒，
      entry_size 12416 减去前面 416 字节，共 3000 个 DWORD 的容量；
    - 每 250ms 读一次，取「最长的一段连续像帧时间的值」作为样本集
      （环形缓冲未写入的位置是 0，垃圾数据不在这一段里）；
    - 校验：这段的均值换算出的帧率必须落在 RTSS 自报平均帧率的 0.6~1.6 倍之间，
      否则说明该 RTSS 版本的 entry 布局不同，自动放弃并退回下面的近似采样；
    - 1% Low = 把窗口内所有帧按帧时间降序排列，取最差 1% 的帧做算术平均，
      再换算成帧率。每帧一个样本，没有任何插值或近似。
    这是和 NVIDIA FrameView / PresentMon 同一档的逐帧精度。

  v2.2 回退路径（RTSS 版本过老、没有该数组时）：
    - 采样线程以 8ms 周期读 RTSS 帧计数器（同时把系统定时器分辨率提到 1ms）；
    - 按「累积满 3 帧或 120ms」切分样本，样本粒度接近单帧；
    - 显式检测计数器回退，跨清零的那一段整段丢弃，不再产生假样本；
    - 单段超过 1 秒（暂停/读条/切出）直接丢弃，不算卡顿；
    - 统计窗口内所有样本按帧时间降序排列，按帧数累计到总数的 1%，加权平均后换算 FPS。

  两条路径共同点：切到桌面看一眼不会清零 —— 前台不是游戏时，代理会继续沿用
  那个仍在出帧的 RTSS 条目，超过 3 秒没有数据才清空。

  合成帧时间对照（真值 = 直接对逐帧数据取最差 1% 的加权平均）：
      场景                        真值   回退路径   旧版
      120fps + 每3秒 45ms 卡顿     51.6     55.3    72.9
      60fps 平稳                   56.6     56.9    58.1
      144fps + 每2秒 70ms 卡顿     32.8     37.3    51.0
      30fps  + 每5秒 120ms 卡顿    10.4     13.8    16.0
  单位 fps。旧版在有卡顿的场景里普遍高估 40%~55%，回退路径收敛到 10%~15% 以内，
  逐帧路径没有近似误差。

  实机验证（本机 WorkBuddyAI.exe，60fps WebView2）：
      逐帧样本 1027 帧，均值 59.19 fps（RTSS 自报 60.1 fps，偏差 1.5%）
      逐帧分布 min 0.60 / p50 16.66 / p99 28.09 / max 89.78 ms
      1% Low = 22.3 fps（最差 11 帧平均 44.88 ms）

  设置页会显示当前走的是哪条路径（「逐帧数据」/「回退采样」）；如果顶部出现
  黄色告警，说明跑的还是 v2.1 之前的旧代理，1% Low 修复没有生效。

【注意：改了代理源码必须重新编译】
  mro_agent.cs 是源码，改完不会自动生效，要双击 mro-hud\agent\build.cmd 编译，
  然后关掉再打开「MRO HUD」插件。编译失败时旧的 mro_agent.exe 保持不变，
  错误信息写在 agent\build.log。

【监控台（标签页）界面说明】
  CPU 卡       结温、占用率、当前频率、封装功耗，温度条按 75℃/88℃ 变色。
  GPU 卡       核心温度、占用率、核心频率、显卡功耗。
  CPU/GPU 风扇 实时 RPM + 0~5000 RPM 进度条 + 转速百分比，扇叶随转速旋转。
  控制条       「强冷」调用 set_fan_boost；办公/均衡/狂暴/自定义调用 set_power_mode，
               与主界面、机身 Q-Key 实体按键实时同步。
  温度走势     最近 90 个采样点（约 90 秒）CPU/GPU 折线 + 面积图。
  显存卡       已用/总显存、占用条、核心频率、显存频率、GPU 功耗。
  系统条       电池养护上限、交流/电池、刷新率、Win 键锁定、OEM 服务状态。

【安全边界】
  - 温度/风扇/功耗等全部走 OpenRevo 语义化 IPC：get_hardware_status /
    set_fan_boost / set_power_mode，不读写裸 EC 寄存器、不加载驱动；
  - 代理只读取系统内存计数与 RTSS 共享内存，全部只读；
  - 不联网、不上传数据；不做注入、不 hook 游戏进程。
  - 会改动硬件状态的只有你主动点的「强冷」与「性能模式」。

【轮询与开销】
  - 标签页：每 1.5s 调一次 get_hardware_status；若宿主主动推送遥测则降频到 6s 兜底；
  - 设置页：1s 一次 /api/sensors，顺带同步 HUD 设置与帧率读数；
  - HUD：1.5s 一次遥测 + 1s 一次本地代理（进程间回环 HTTP，开销可忽略）；
  - 代理内部：1% Low 采样线程 8ms 一次读共享内存（约 0.2% CPU），
    排序节流到 200ms 一次；只在代理运行期间把系统定时器分辨率提到 1ms；
  - 关闭挂件后代理随 auto_stop 退出，不常驻。

【实测情况】
  - OpenRevo v0.9.2 (6ee7ba9) 实测：重启后顶栏出现「MRO 硬件监控台」，
    实时读到 CPU 63℃ / GPU 51℃ / 风扇 4657·4723 RPM / 功耗 / 显存 / 280Hz；
  - 新版 HUD 用真实代理实测：内存 12.4GB、RTSS 前台进程 FPS 57~100、
    帧时间 9.9~17.5ms（以 Oopz 窗口为前台样本）。
   - RTSS 自动启动实测：先退出微星小飞机、结束 RTSS 进程，挂件保持运行，
     约 1 秒内代理自动拉起 RTSS（父进程 = mro_agent.exe），FPS 行变为
     「RTSS 就绪」；随后重新打开微星小飞机，它直接复用该 RTSS，不再重复启动。

【兼容性】
  - OpenRevo v0.9.x（清单 min_host_version = 0.9.0）；
  - 通过父窗口 __TAURI_INTERNALS__.invoke 调用宿主命令（0.9.2 实测可用），
    同时兼容新版宿主的 postMessage 遥测推送；
  - 代理为 .NET Framework 4.x 控制台程序（Windows 10/11 自带），x64；
  - 无 GPU 的核显机型：GPU 行显示 --，其余功能不受影响；
  - 未安装 RTSS：HUD 仍可用，只是 FPS 行提示「RTSS 未运行」。

【排错】
  1. 界面显示「连接中 / 等待遥测」
     - 确认是从 OpenRevo 的「插件」页打开的，不是浏览器双击 index.html；
     - 插件页右上角「刷新」，或重启 OpenRevo。
  2. HUD 内存显示 --、RTSS 行「传感器代理离线」
     - 看插件列表里 mro-hud 的服务指示灯是否为绿；若不是，点「启动服务」；
     - 挂件每 20 秒会自动请求宿主重启代理，也可关掉挂件重开；
     - 检查 18946 端口是否被占用：netstat -ano | findstr 18946；
     - 代理日志：%APPDATA%\OpenRevo\plugins\mro-hud\agent\agent.log。
  3. RTSS 行一直「RTSS 未运行」
     - 确认本机装了 RivaTuner Statistics Server（默认
       C:\Program Files (x86)\RivaTuner Statistics Server\RTSS.exe）；
     - 若装在非默认位置，给代理加 --rtss-path 指向 RTSS.exe（改 manifest.json
       的 service.args），或设置环境变量 RTSS_PATH；
     - 看 agent.log 里是否有「rtss start failed」以及具体错误。
  4. RTSS 已运行但 FPS 一直是 --
     - RTSS 只挂钩启动晚于它的进程；先开 RTSS（挂件会自动开）再进游戏；
     - 确认 RTSS 的「Framerate」在游戏里能正常显示；
     - 以管理员身份运行 OpenRevo（跨权限读取共享内存更稳）。
  5. 顶栏没有出现页签 / HUD 打不开
     - 检查目录层级与 agent 子目录是否完整；
     - 打开 %APPDATA%\OpenRevo\config.json，把 custom_plugin_toggles 中
       对应项改成 false 后重启，可安全跳过问题插件。
  6. 插件导致界面异常
     - 同上，用 config.json 的 custom_plugin_toggles 关闭对应插件。

【卸载】
  1. 在「插件」页停用三个插件（会自动停掉代理）；
  2. 删除 %APPDATA%\OpenRevo\plugins\mro-monitor、mro-hud 与 mro-hud-settings 文件夹；
  3. 重启 OpenRevo。
